# Next Toss UI

`my-news-front`의 화면과 컴포넌트를 구현하거나 개선할 때 이 스킬을 사용한다. 목표는 토스 디자인 톤의 명확하고 빠른 UI를 기존 구조와 충돌 없이 만드는 것이다.

## 기본 방향

- 첫 화면은 사용자의 핵심 행동을 바로 수행할 수 있게 구성한다.
- 정보 위계는 제목, 보조 설명, 주요 액션, 보조 액션 순서로 분명하게 둔다.
- 색상은 절제하고, 상태와 액션을 구분하는 데 집중한다.
- 카드, 탭, 버튼, 리스트는 기존 컴포넌트와 클래스 패턴을 먼저 확인한다.
- 화면 문구는 짧은 한국어로 작성하고, 기능 설명을 UI 안에 길게 노출하지 않는다.
- 버튼에 아이콘이 필요하면 `lucide-react`를 우선 사용한다.

## 작업 흐름

1. `my-news-front/app`, `my-news-front/components`, `my-news-front/lib`, `my-news-front/hooks`에서 관련 패턴을 먼저 찾는다.
2. 공통 CSS 변수, 공통 클래스, 기존 컴포넌트 props를 확인한다.
3. 새 UI는 기존 컴포넌트를 조합하고, 새 추상화는 중복이 실제로 생길 때만 추가한다.
4. `margin`, `padding`, `width`, `overflow`, `font-size` 변경은 전역 영향과 반응형 충돌을 확인한다.
5. 모바일과 데스크톱에서 텍스트 넘침, 요소 겹침, 가로 스크롤, 버튼 높이 변화를 점검한다.
6. 변경 후 가능한 검증을 실행하고 결과를 보고한다.

## CSS 규칙

- 섹션/아이템 내부 패딩은 공통 변수 또는 공통 유틸 클래스로 관리한다.
- 상하좌우 패딩 값을 컴포넌트마다 개별 하드코딩하지 않는다.
- 공통 UI의 `font-size`, `padding`, `margin`, `width`, `overflow`를 바꿀 때는 다른 화면에 미치는 영향을 확인한다.
- 고정 형식 UI는 `min/max`, `grid`, `aspect-ratio`, `flex` 기준을 명확히 둔다.
- 긴 한국어 문구와 숫자/영문 혼합 텍스트가 버튼이나 카드 밖으로 넘치지 않게 한다.

## 검증

작업 범위에 맞게 좁은 명령부터 실행한다.

```bash
npm run lint --workspace my-news-front
npm run build --workspace my-news-front
```

시각 변경이 있으면 가능한 경우 브라우저로 실제 화면을 열어 모바일/데스크톱 폭에서 확인한다. 검증을 못 했으면 이유와 다음 확인 방법을 말한다.

## 최종 응답

변경한 화면/컴포넌트, 디자인 기준, 실행한 검증, 남은 확인 사항을 짧게 정리한다.
