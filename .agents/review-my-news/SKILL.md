# Review My News

이 저장소의 변경 사항을 리뷰할 때 이 스킬을 사용한다. 스타일 취향보다 실제 동작, 회귀 가능성, 운영 위험, 검증 공백을 우선한다.

## 리뷰 우선순위

1. 사용자에게 보이는 버그나 데이터 손상 가능성
2. 인증, 쿠키, JWT, CORS, 개인정보, 비밀값 노출 위험
3. Prisma 마이그레이션, nullable/default, relation 변경에 따른 운영 DB 위험
4. 외부 뉴스 API, 스케줄러, 크롤링성 로직의 실패/재시도/타임아웃 문제
5. 프론트 CSS의 겹침, 잘림, 가로 스크롤, 공통 UI 회귀
6. 누락된 테스트, lint/build 실패 가능성
7. 설정 변경과 문서 불일치

## 리뷰 흐름

1. 변경 파일과 영향 범위를 파악한다.
2. 프론트, 백엔드, DB, 문서, 배포 중 어느 영역인지 분류한다.
3. 실제 런타임 동작이 깨질 수 있는 경로를 먼저 검토한다.
4. 테스트나 문서가 빠져도 위험이 낮으면 낮은 우선순위로 표시한다.
5. 근거 없는 추측은 피하고, 파일/라인 기준으로 지적한다.

## 출력 형식

문제가 있으면 심각도 순서로 먼저 나열한다.

```text
Findings
- [P1] 제목
  파일:라인
  이유와 영향:
  제안:

Open Questions
- 필요한 경우만 작성

Summary
- 짧은 변경 요약 또는 리뷰 범위
```

문제가 없으면 명확히 말하고, 남은 테스트 공백이나 확인하지 못한 범위를 짧게 적는다.

## 우선순위 기준

- `P0`: 배포 즉시 장애, 데이터 손실, 심각한 보안 문제
- `P1`: 주요 기능 회귀, 인증/DB/API 계약 문제, 운영 위험
- `P2`: 특정 조건의 버그, 누락된 검증, 문서 불일치
- `P3`: 유지보수성, 작은 UX 품질, 사소한 정리
