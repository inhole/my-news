# 개인화 구조

## 개요

`My News`는 로그인 없이도 최근 클릭 이력과 관심 카테고리를 바탕으로 맞춤형 뉴스 정렬을 제공합니다.
개인화 데이터는 서버 계정이 아니라 브라우저 로컬 저장소에 보관합니다.

## 핵심 원칙

- 개인화 데이터는 `localStorage`에만 저장합니다.
- 서버는 뉴스 원문, 카테고리, 날씨 데이터를 제공합니다.
- 클라이언트는 사용자 반응을 기반으로 개인화 점수를 계산합니다.
- 별도의 AI 요약 의존성 없이 설명문과 본문 데이터를 활용합니다.

## 저장 데이터

- `anonymousProfile.id`
- `categoryScores`
- `keywordScores`
- `preferredCategorySlugs`
- `preferredKeywords`
- `seenNewsIds`
- `createdAt`
- `updatedAt`

## 점수 계산

```text
personalizedScore = categoryAffinity * 2 + keywordAffinity + freshness - seenPenalty
```

- `categoryAffinity`: 선호 카테고리 반영 점수
- `keywordAffinity`: 기사 제목/설명 키워드 반영 점수
- `freshness`: 최신 기사 가산점
- `seenPenalty`: 이미 본 기사 감점

## 맞춤 뉴스 탭 페이지네이션

`rankPersonalizedNews`는 서버에서 받아온 뉴스 목록을 `preferredCategorySlugs` 기준으로 먼저 필터링한 뒤
점수순으로 정렬합니다. 서버 페이지(1페이지 20건) 안에 선호 카테고리 기사가 하나도 없으면 필터링 결과가
0건이 되는데, 이때 화면에 아무 기사도 그려지지 않아 무한 스크롤 감지용 sentinel 엘리먼트도 렌더링되지
않습니다. 스크롤 기반 `IntersectionObserver`만으로는 다음 페이지를 요청할 방법이 없어 목록이 영구히
비어 있는 것처럼 보이는 교착 상태(deadlock)가 발생할 수 있습니다.

이를 막기 위해 `app/page.tsx`의 `HomeContent`는 다음 조건을 판단하는 순수 함수
`shouldAutoFetchNextPersonalizedPage`(`lib/personalization/personalized-pagination.ts`)를 사용해,
필터링 결과가 0건이고 서버에 다음 페이지가 남아있으면(`hasNextPage`) 스크롤 여부와 무관하게 자동으로
`fetchNextPage()`를 호출합니다.

- 필터링 결과가 계속 0건이어도 `hasNextPage`가 `true`인 동안은 페이지를 계속 가져옵니다.
- `hasNextPage`가 `false`가 되면(더 가져올 페이지 없음) 자동 호출을 멈추고 "일치하는 기사 없음" 빈 상태를 보여줍니다.
- 직전 다음 페이지 요청이 실패하면(`isFetchNextPageError`) 자동 재시도를 멈춰 반복 실패 요청을 막고,
  재시도 버튼이 있는 오류 상태를 보여줍니다. 사용자가 재시도를 누르면 `fetchNextPage()`를 다시 호출합니다.
- 필터링 결과가 이미 있는 상태에서의 스크롤 추가 로딩은 기존과 동일하게 sentinel 기반
  `IntersectionObserver`가 담당하되, 직전 다음 페이지 요청이 실패한 상태(`isFetchNextPageError`)에서는
  스크롤로 다시 트리거하지 않고 명시적인 재시도 버튼을 노출해 반복 실패 요청을 막습니다.

`@tanstack/react-query`의 무한 쿼리는 다음 페이지 요청이 실패해도 최상위 `isError`가 함께 `true`가
됩니다(`isFetchNextPageError = isError && fetchDirection === 'forward'`). 이 때문에 `HomeContent`의
전체 화면 오류 처리는 `isError && !isFetchNextPageError`로 초기/재조회 실패만 가로채고, 다음 페이지
실패는 `PersonalizedSection` 내부의 재시도 UI가 담당하도록 분리했습니다. 그렇지 않으면 다른 탭(헤드라인,
트렌딩 등)을 보고 있어도 개인화 탭의 다음 페이지 실패로 전체 화면이 오류로 가려질 수 있습니다.

`PersonalizedSection`은 빈 상태를 네 가지로 구분해 렌더링합니다: 다음 페이지를 찾는 중(로딩 스피너),
다음 페이지 요청 실패(재시도 버튼), 선호 카테고리와 일치하는 기사가 끝까지 없는 소진 상태(카테고리 필터
전용 안내 문구), 관심 반응 자체가 아직 부족한 기본 빈 상태(기존 안내 문구). 이미 기사가 표시된 상태에서
다음 페이지 요청이 실패하면 sentinel 영역에 동일한 재시도 버튼을 보여줍니다.

## 요약 재생성 버튼과 관리자 전용 API

`POST /news/:id/summary`는 `refresh=true`(강제 재생성) 요청에 한해 `x-news-admin-key` 관리자 API 키를
요구합니다. 공개 클라이언트는 관리자 키를 가질 수 없으므로 `app/news/[id]/page.tsx`의 요약 버튼은 이미
요약이 있으면 재생성 버튼을 아예 노출하지 않고, 요약이 없을 때만 `summarizeNews.mutate(false)`로
(`refresh=false`) 최초 생성만 요청합니다. 캐시된 요약은 그대로 계속 보여줍니다.
